# examples —— 可以直接拿来用的样例

| 文件 | 是什么 |
|---|---|
| `card.example.json` | 一张**完整、能过校验**的角色卡。可以导进人物卡页（③导入/导出），也可以当格式参考 |
| `lore.example.txt` | 一段角色介绍样例。可以贴进人物卡页第①段「出表并填」，看它怎么抽出约束 |

## 这两份是怎么来的

`card.example.json` **不是手写的** —— 它由真实的填表流程产出：

```
lore.example.txt
  → 出表（8 个格子，格式见 docs/CARD.md）
  → 启发式填表（抽到 6 格：口癖、禁用词、称呼、气质、背景、性格）
  → 逐格确认
  → card.example.json
```

产出的 `speechStyle` 是占位符「（待填：说话风格）」—— 因为启发式**没在原文里找到说话风格的依据**，
它就留了空。这一步我随后手工补成了「短句、爱吐槽，很少用感叹号」。
**留空是正确行为**：没有依据就不编，这是这套流程的立场。

## 自己试一遍

```bash
# 1) 离线跑通全流程（合成数据，不碰你的真实存档）
node tools/demo.mjs

# 2) 看这张卡能不能过校验 + 需要哪些桌宠动作
npm run art -- --measure

# 3) 在界面上用：npm start，右键桌宠打开人物卡页，
#    把 lore.example.txt 的内容贴进第①段，点「出表并填」
```

## 注意

`card.example.json` 里的 `game` 是 `someday`（虚构的游戏标识）。
**记忆是按 `game` 归属的** —— 换成你实际在玩的游戏标识，才会用上对应的记忆。
