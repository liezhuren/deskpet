## 1. 设计立场（决定代码怎么组织，别推翻）

需求原话（用户给的项目描述）：
> 从各种单机游戏运行过程中读取它的日志，和每一次的存档更新，结合网上的角色介绍以及用户的提示词，
> 实现让游戏角色成为一个能和用户互动的智能桌宠。包含前端、api 配置页、人物卡生成/导入页。
> 根据用户传入的游戏立绘绘制出不同风格、不同动作的桌宠。
> 希望达到的效果是类似于用户好不容易打败了一个 boss，存好档的松懈时间和他交流，
> 或者角色死亡后与用户交流，**这样的度再加上读取日志和存档的局限应该是刚刚好的**。
> 退出游戏后，桌宠能带有刚才游戏的记忆继续与用户交流。
> 立绘生成会根据角色的官方人设生成不同的动作，比如偏活泼一些的，不止是桌宠傻傻地站着，
> 当用户长时间不理人时会做出无聊的动作。

**这个项目的真问题有两层**，第二层比第一层重要得多：

| 层 | 问题 | 本项目的回答 |
|---|---|---|
| 表层 | 能不能生成角色卡 / 能不能生成动作图 | 模型很擅长，不是难点 |
| ★ 里层 | **怎么证明「度」是对的、角色没跑偏** | 状态机 + 校验器 + **时机引擎 + 可观测指标** |

### 1.1 三条贯穿全局的原则

- **P1｜只报事实，其余用问的。** 确定性代码给出的事实（"存档变了""多了 3 条进度""游戏退了"）可以直说；
  一切细节必须用疑问句，不许编。这同时解决了"模型不许发明剧情"。
- **P2｜局限是设计资源，不是缺陷。** 桌宠只看得见"存档被写入"，看不见细节 —— 所以它只能**问**，
  而"问"就是交互本身。**推论：内容解析是锦上添花，时机才是主线。**
  即使一个游戏完全解不开（实测确实有 18 个这种存档），仅凭"存档文件被写入"就足以驱动时机引擎。
  **这条决定了实现顺序：时机引擎先于解析器。**
- **P3｜先量出来，再谈好不好。** "度刚刚好"必须落成可测指标（每小时发言次数 / 触发延迟 /
  被忽略率 / 专注期发言次数必须为 0），否则无法回归、无法比较。

### 1.2 分层与硬约束

| 层 | 职责 | 为什么这样分 |
|---|---|---|
| `core/` | 纯逻辑，**零依赖**，全部可单测 | 与引擎、与 Electron 都无关 |
| `gameio/` | 引擎 adapter（unity / godot / rpgmaker） | 只负责"翻译成统一事件形状" |
| `presence/` | ★ 时机引擎：什么时候可以开口 | 见 P2、P3 |
| `dialogue/` | 表达层，provider 可插拔 | 模型只做表达，不做事实 |
| `app/` | Electron 外壳 + 界面 | 换壳不影响下面任何一层 |

**硬约束**：
- 角色卡分 `hard`（可校验）/ `soft`（自由描写）两层，**只有 hard 层能进校验器**
- 模型**不许发明剧情**：事件与进度由 `gameio` + `core/events.mjs` 提供
- 没接模型、没接图像 API 时全链路仍要能跑（模板 provider + 程序化兜底）

## 3. 关键设计决定（含理由）

### 3.1 角色卡为什么分 hard / soft
一整段自然语言写的人格**无法验证**：模型偶尔说错你只能肉眼看，改一版提示词也无法判断好坏。
所以把可判定的部分抽成结构化字段（`speechTics` / `forbiddenWords` / `addresses` / `avgLength` /
`emojiPolicy`），**只有这部分进校验器**。

### 3.2 为什么"校验器"比"更好的提示词"有用
提示词是概率约束，校验器是硬约束。有了校验器才能**回归**（改提示词后跑同一批输入比违规率）、
**定位**（违规归到具体条目）、**拒绝**（不合格的回复重试或降级到模板）。

### 3.3 diff 的粒度规则：**一律展开到叶子**
新增一个道具 `{id:'sword', atk:5}` 产出 `$.items[id=sword].id` 与 `$.items[id=sword].atk` 两条，
而不是一整条元素。理由：**路径越细规则越容易匹配；聚合容易，拆分难。**
要还原成"某元素整体新增"，按 `$.items[id=sword]` 前缀聚合即可。

### 3.4 数组必须分三种策略（这是 diff 最要紧的设计）
| 数组形状 | 策略 | 为什么 |
|---|---|---|
| 原始值数组 | **集合 diff** | `triggered_stories` 是字符串数组，索引 diff 会把它判成"全线位移"，毫无用处 |
| 带 `id`/`name` 的对象数组 | **按 key 配对**，路径 `$.items[id=sword].hp` | "某道具被消耗"应是同一条路径上的数值变化 |
| 其余 | 索引 diff | 兜底 |

### 3.5 解码链必须能降级，且**认不出来不是失败**
`decodeSaveFile` 无论内容能否解析，**永远返回 sha256 与 size**（P2 的落地）。
对"正常解不开"**不抛异常**，返回 `ok:false` + `notes` 说明卡在哪一步。

### 3.6 按内容嗅探，不按扩展名
实测教训见 §2 表格第一行。extension 会骗人，magic bytes 不会。

### 3.7 ★ 「玩家专不专心」只能靠系统空闲判断，不能靠日志活动
Unity 的 `Player.log` 在进行游戏时几乎不产出内容（实测单个文件 6MB 全是引擎噪声），
所以"存档之后有没有新日志行"根本区分不出「放下手柄」和「接着打下一段」。
真正的判据是**系统空闲时长**。因此静默判定拆成 `activity`（文件/日志动静）与
`relaxed`（键鼠空闲）两个独立信号，**要开口必须 relaxed 够久**。

### 3.8 ★ 「到了静默窗口但玩家还在玩」→ 继续等，不丢弃
若在那里丢掉待发言，就等于要求玩家必须在存档后 20 秒内停手，与用户原话
「存档后接着打一会儿、再放下手柄」直接冲突。现在是**一直等到玩家松懈**，
只受 `pendingTtlMs`（保守档 5 分钟）兜底，免得拿十分钟前的存档去搭话。

### 3.9 ★ 调整空间被「实际读得到什么」框住
用户要「留给用户调整的空间」，同时说「如果读不出信息，还是只给保守选项」。
这两句合起来是硬规则：**把档位调高却读不到新东西，只会逼桌宠编内容**。
所以 `capability`（adapter 自述能读出哪些事件类型）**决定档位上限**；
只读得到 `save`/`exit`/`manual` 的 adapter 一律封顶在保守档，并给出理由。

### 3.10 ★ diff 得对不对，取决于 adapter 懂不懂数据语义
RPG Maker 的 `$gameSwitches._data` 是**稀疏、下标有意义**的原始值数组（下标就是开关 id），
而 `core/diff.mjs` 对原始值数组走**集合 diff**（那是为 `triggered_stories` 那种列表设计的）。
两者冲突会**静默丢事件**：开关 3 变 true、开关 4 变 false ⇒ 集合里 true 一进一出，
**互相抵消，报"什么都没变"**。
所以 adapter 可以提供 `normalizeSave()`，把"下标当键"的容器转成稀疏对象再交给 diff。
这是 adapter 的职责 —— `core/diff.mjs` 不该去猜某个引擎的数组是什么意思。

### 3.11 ★ 首帧只作基线，绝不产事件
第一次看某个目录时没有"上一次"可比，也就无从判断"刚刚发生了什么"。
若把整个存档当成一堆 added、整份日志当成一堆事件，桌宠就会对着一个
它刚认识、玩家也没刚做过什么的游戏开口。所以首帧只记录基线（sha256 / 解码值 / 日志偏移）。
**基线必须连解码值一起存** —— 只存 sha 的话第二次就没得比，diff 分支会被永远跳过（踩过）。

### 3.12 ★ 角色卡的「自相矛盾检查」是它存在的理由，所以要查得够狠
`card.mjs` 里现在有 6 类矛盾检查，每一类都对应「按此卡**怎么写都不对**」：
口癖是禁用词 / 口癖含禁用词 / **称呼本身是禁用词** / `mustMention` 的词比长度上限还长 /
称呼比长度上限还长 / 要求带表情但长度上限装不下。
后四类是这一轮补的 —— 它们比前两类更隐蔽，因为称呼只有一两个、长度上限也很少有人细看。

**为什么值得做**：这类错人工几乎发现不了，但机器一查就出来；
而且不查的话，废卡会一路流到校验器，表现为"这个模型怎么老是违规"，让人去调提示词 ——
**根因却是卡本身不可能被满足**。测试里专门有一条：拿一张矛盾卡喂给 `lintBatch`，
断言 `passRate` 直接掉到 0.5，证明"不可用"是**实测出来的**，不是我声称的。

`npm run demo` 按**数据实际流过系统的顺序**跑一遍并打印真实产生的值：

### ★ 角色卡格式：规范在 `core/card-spec.mjs`，文档是**生成**的
用户明确要求过：「我想要一个规范的角色卡格式，**不要让 llm 即兴生成**，而是让他类似于填表一样地生成角色卡。」

所以格式只在 `core/card-spec.mjs` 里写**一次**，三样东西都从它派生（于是不可能出现"文档说的"与"代码查的"不是一回事）：
① 校验规则（`validateCard` 的 `HARD_KEYS` / 枚举 / 范围都从 spec 取）
② 填表用的空表与提问文案（`lore/fill.mjs`）
③ 人读的格式文档 [`CARD.md`](CARD.md) —— **由 `node tools/gen-card-doc.mjs` 生成**，
   并且有一道测试盯着它与 spec 逐字一致（手改文档会测试失败）

每个字段都必须回答四件事（缺一个就会出现"看起来能填、其实没人管"的字段）：
哪一层（meta/animation/soft/hard）· **谁有资格填**（derived/user/model）· 类型与取值范围 · 填错会怎样。
其中「谁有资格填」是这次改造的核心：

| fill | 含义 |
|---|---|
| `derived` | 程序派生（如 `id`），**模型与用户都不该填**；模型填了直接丢 |
| `user` | 只能由用户指定（`style` / `emojiPolicy` 这类主观选择，没有"正确答案"可抽） |
| `model` | 模型可以提议填入；标了「需出处」的还必须给 quote，且 quote 要能**逐字对上**原文 |

**填表流程有六道闸门**（`lore/fill.mjs`）：
1. 出空表（格子由 spec 定死）→ 2. 交给模型填 → 3. **未登记的格子直接拒**（这就是"不许即兴"）
→ 4. 逐格按 spec 校验类型/枚举/范围 → 5. hard 层的格子**必须有 quote 且能对上原文**
→ 6. **逐格确认**才写入（提议 ≠ 生效）

实测演示（一个"会编东西"的模型）：它填了 8 格，其中 2 格被挡下 ——
一个是它自己加的 `persona.hard.favoriteColor`（未登记），一个是 `mustMention`（不是给模型填的）。
剩下 6 格经用户确认后写入，卡从"草稿"变成正式卡，**动作清单也跟着变了**（气质 lively ⇒ 多出 greeting/happy）。

## 5. 踩坑记录（**本会话真实踩到的**，不是抄来的）

| # | 坑 | 教训 |
|---|---|---|
| 1 | `node --test tests`（目录形式）在 Node 24 + 无 `package.json` 时直接 `Cannot find module`。**测试命令本身是坏的，很容易被忽略** | 测试入口要钉死在 `package.json` 的 script 里，用 `node --test "tests/**/*.test.mjs"` |
| 2 | UTF-8 BOM 被 `tryJsonAtOffset` 当成"前 3 字节二进制头部"，把普通 JSON 误报成 `json@offset`。**实测 `costume.sav` 开头真的是 `ef bb bf`** | BOM 必须在**最外层**剥掉，不能只在文本分支里剥 |
| 3 | 前导空白（`"  \r\n{...}"`）同样被当成二进制头部 —— 与坑 2 同一类 | "跳过 N 字节后是 JSON"的判断必须排除"跳过的全是空白" |
| 4 | 文档写 `format` = 最外层格式，代码返回的却是最内层。**文档与代码不一致，只有测试能发现** | 文档里描述的语义必须有断言钉住；补 `content` 字段区分"外层容器"与"最终解出的格式" |
| 5 | `deepEqual` 兜底函数内部有 64 层递归上限，低于被测结构深度 ⇒ 两个**相同**的深结构被误报成"有变化"，而这个假信号会一路传成"存档有更新" | 兜底逻辑自己不能有一条深度红线；改用显式栈 |
| 6 | 我自己写的测试断言错了 **5 处**（`counts` 少算一个 removed、正则测的是完整路径串、`numberTolerance` 断言与注释自相矛盾…） | **测试也会写错，不只是代码**。失败时先分清"代码错"还是"断言错"，别急着改代码去凑断言 |
| 7 | `Select-Object -First N` 截断管道 ⇒ node 收到 EPIPE ⇒ `exit code 1`，看起来像命令失败 | 管道截断导致的退出码 1 不是真失败 |
| 8 | PowerShell `>` 重定向写 **UTF-16**，`Set-Content -Encoding utf8` 写 **BOM** ⇒ `JSON.parse` 两种都读不了 | PS 与 Node 之间传数据要显式处理编码；读端一律先 `replace(/^\uFEFF/,'')` |
| 9 | LocalLow 里混着**显卡驱动的着色器缓存**（`AMD/` 下 8MB 二进制块）与 Unity 崩溃转储（`*.framedump` 单个 25MB） | 扫描前必须过滤，否则统计全是噪声 |
| 10 | 真实存档含玩家名/日期/游戏内容，**不能提交进仓库**，但假数据又证明不了真实世界 | 夹具合成 + 真实文件本机对拍（不存在则 skip）双轨 |
| 11 | 我按 npm 元数据写下"LZString 1.5.0 / MIT 参考实现"，**实测都不对**：`package.json` 写 `1.5.0`+`MIT`，但源码文件内注释写 **1.4.5**、版权头写 **WTFPL v2**；而且实测 `compress(x,6) === compress(x,16)` —— 该文件的 `compress` **忽略 `bitsPerChar`** | 元数据不等于事实。写进文档前至少打开源文件看一眼；子代理提出的疑点也要自己复验（这次它是对的，我错了） |
| 12 | 时机引擎里把「收紧系数」乘到了**绝对时间戳**上。用小数字测试时看不出来，一放到真实 epoch 毫秒（~1.7e12）冷却就被放大成**几十年** | 量纲错误要靠**量级正确的测试数据**才能发现。`tests/presence.test.mjs` 因此刻意用 `1_700_000_000_000` 起点，而不是 0 |
| 13 | 把「到了静默窗口但玩家还在玩」处理成**丢弃**待发言。这等于要求玩家必须在存档后 20 秒内停手 —— 与用户原话「存档后接着打一会儿再放下手柄」直接冲突 | 设计规则要拿用户原话去对；现在是「继续等 + `pendingTtlMs` 兜底」。测试 `★ 存档后接着打两分钟再放下手柄 → 仍然开口` 专门钉住它 |
| 14 | 一口气写错 3 个测试断言（合并窗口会**重新计时**、20 分钟不够 25 分钟冷却、场景压根没走到「等待」分支） | 同一个毛病在本会话犯了 8 次。**失败先怀疑断言**：先手算一遍时序，再决定改代码还是改测试 |
| 15 | **噪声表把收尾标记吃掉了**：`[Physics::Module]` 同时出现在噪声表和收尾标记里，而噪声过滤跑在前面 ⇒ "正常退出"**永远**识别不出来 | 两张规则表有重叠时，**先判有意义的、后过滤噪声**。别指望两个正则列表永远互不重叠 |
| 16 | 信号词规则写 `story`，而 Godot 的字段叫 `triggered_stories`（**复数**）⇒ 整整一类进度字段全部**静默漏掉**，不报错、只是什么都不产出 | 这类"静默不产出"最难发现。词表要覆盖真实字段名的形态变化，并写一条专门钉住复数的回归断言 |
| 17 | `capabilityOf` 返回 `Object.freeze` 的数组，测试里 `.sort()` 直接抛 —— 顺带暴露出返回顺序依赖调用方插入序 | 对外返回值要么**已排序**（顺序由内容决定），要么别冻结。冻结 + 未排序 = 既不能改又不可比 |
| 18 | 测试里写 `sessionEvents(...).at ?? T0` —— 那是 `Array.prototype.at`（一个函数），不是元素属性 | 数组要取元素：`[0].at`。这类笔误只有断言真跑起来才会暴露 |
| 19 | **首帧基线只存了 sha、没存解码值** ⇒ 第二次观测没有"上一次"可比，diff 分支被永远跳过。表现是"只能报存档已更新、永远读不出进展"，**不报任何错** | 基线要存够"下次能比"的信息。**静默不产出**是最难查的一类 bug，链接路的测试才能暴露 |
| 20 | 增量读日志时**无条件丢掉半截首行** ⇒ 把刚追加的那一整行吃掉，表现是"日志明明有新增却不产事件" | 「丢半行」只在**从文件中间切进来**时才对。正确做法是：只消费到最后一个换行为止、把偏移记在**行首**，于是永远不需要丢 |
