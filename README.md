# 游戏角色陪伴桌宠 · 读存档与日志的桌面 Agent

一个本地运行的桌宠。它读你正在玩的单机游戏的**日志与存档更新**，结合角色卡，让游戏里的角色
成为能在桌面上和你互动的对象。

难的不是"能说话"，是**什么时候不说**。所以这个项目里最重的一块是时机引擎：
它在存档写入、角色死亡、退出游戏这些"泄压点"上找机会，在你还握着键鼠的时候闭嘴，
在你放下手柄的那一刻才开口。

---

## 功能

- **读游戏** —— 按引擎可插拔（RPG Maker MV/MZ · Unity 2D · Godot），通用结构 diff → 事件映射。
  存档解不开也能用：仅凭"文件被写入"就足以驱动时机引擎
- **角色卡** —— 规范格式（hard/soft 两层 + 校验器）。**不让模型即兴生成**，而是先出表、再让它往格子里填
- **桌宠素材** —— 立绘 → 三种画风 × 多动作，两条质量闸门自动判定"偷懒"与"跑形"
- **桌面外壳** —— 透明置顶桌宠窗（默认穿透点击，不挡游戏操作）+ 设置页 + 人物卡页
- **时机引擎** —— 专注期静默、松懈才开口、节流与预算；**沉默时给得出理由**
- **跨会话记忆** —— 退出游戏后还记得上一局；被忽略会收紧，被回应会放松

## 使用

需要 **Node ≥ 22**。运行时只依赖 Electron。

### 桌面（正题）

```bash
git clone git@github.com:liezhuren/pet.git
cd pet

# ⚠ Windows 上装 Electron 必须走镜像，否则 postinstall 会**静默失败**
#   （npm 退出码 0、包也装了，但没有 electron.exe）
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
npm install

npm start
```

桌宠出现在桌面右下角。**默认穿透点击** —— 指针压在它身上时才可点，其他位置的点穿到游戏里
（否则它会挡住游戏操作）。拖动移动 · 单击 = 主动搭话 · 双击 = 设置页 · 右键 = 人物卡页。

> 若 `node_modules/electron/dist/electron.exe` 不存在，补救办法是 `cd node_modules/electron; node install.js`。

### 先看它能干什么（不需要游戏、不联网）

```bash
npm run demo      # 一条命令跑通全流程：读游戏 → 角色卡填表 → 多风格素材 → 一局陪玩 → 跨会话记忆
npm run longrun   # 长跑验证：模拟 6 小时，断言"度"守在界内且没有泄漏
```

两个脚本都**只用临时目录里的合成存档**，绝不碰你的真实游戏存档；也不会假装调了模型或云端生图。

### 命令行

```bash
npm run games                    # 列出本机可识别的游戏目录
npm run probe                    # 扫真实存档，报告解码链成绩
npm run inspect -- <游戏目录>     # 单个目录的完整报告：引擎 / 可读能力 / 生效档位
npm run art -- --measure         # 素材层的实测值（两条质量闸门）
npm run art -- <输出目录> --style pixel   # 指定画风生成（soft / pixel / line）
npm test                         # 627 条断言
```

## 它说出的话

在一款真实 Unity 游戏上跑完整链路（存档差异 → 事件 → 决策 → 表达），桌宠说出的是：

```
……不是，你存档了？是打完了一段想留个底，还是准备收手了？
……不是，你怎么了？想聊点什么？
```

注意这两句都**没有**复述 `$.hPoint：9454→9461` 或 `SaveData1.dat` ——
原始摘要只用来判断「玩家大概在忙什么」，**细节一律用问的**。

几项会单独说明的内容：

- **「可直说」与「必须问」是分开的。** 存档了就是存档了，这是事实；但"为什么存档"只能问。
  表达层拿到的事实清单与待问清单是两份东西，模型只许在后者里发挥
- **不达标就不说。** 生成的话要过校验器（口癖、禁用词、称呼、长度、表情策略）。过不了就**退回重试，
  再不行就保持沉默** —— 宁可不说话，也不说角色不会说的话
- **沉默给得出理由。** "被节流 / 还在专注继续等 / 等太久作废 / 本小时预算用完"，每条都有计数
- **口癖单句没有不判错。** 偶尔漏掉口癖是自然的，整批都没出现才会被统计出来

## 时机引擎：度是怎么落地的

三条闸门叠在一起：

1. **防抖合并** —— 20 秒内的多次触发合成一次（一次存档会同时产生存档/进度/道具几个事件）
2. **静默窗口** —— 事件之后要静默一段时间才可能开口，否则刚存完档就说话会像监视
3. **节流 + 预算** —— 全局冷却、按事件类别的冷却、每小时发言上限

玩家还握着键鼠时，待发言**不被丢弃而是继续等**（记 `waitedForFocus`）——
因为"存档后接着打一会儿、再放下手柄"依然是松懈时间。要玩家必须在存档后 20 秒内停手就太苛刻了。

**6 小时模拟实测**（`npm run longrun`，11/11 断言通过）：

| 项 | 实测 |
|---|---|
| 事件 | 349 条（58.2/小时） |
| 主动开口 | 8 次，**全部落在「刚存完档往后一靠」/「中途休息」/「退出游戏」** |
| **玩家正在打时开口** | **0 次** |
| 开口时的最小空闲 | 10.0 秒 = 门槛（没有贴着边界说话） |
| 触发延迟 | p50 70s · max 148s —— 这就是"等松懈"的代价 |
| 没说的原因 | 还在专注继续等 6448 · 等太久作废 3 · 冷却中 20 |
| 状态体积 | 峰值 **23 KB**（没有泄漏） |

## 角色卡格式

格式只在 [`core/card-spec.mjs`](core/card-spec.mjs) 里写**一次**，三样东西都从它派生：
校验规则、填表用的空表、人读的规范 [`docs/CARD.md`](docs/CARD.md)（**文档是生成的**，
有一道测试盯着它不许与 spec 漂移）。

每个字段都要回答四件事：**哪一层 · 谁有资格填 · 类型与取值范围 · 填错会怎样**。其中「谁有资格填」是核心：

| fill | 含义 |
|---|---|
| `derived` | 程序派生（如 `id`），**模型与用户都不该填** |
| `user` | 只能由用户指定（`画风` / `表情策略` 这类主观选择，没有"正确答案"可抽） |
| `model` | 模型可以提议填入；标了「需出处」的还必须给出能在原文里找到的引文 |

**不让模型即兴生成，而是先出表、再填**：空表的格子由 spec 定死，模型只负责把值填进去 ——
**未登记的格子直接被拒**。实测一个"会编东西"的模型：它填了 8 格，2 格被挡下
（自己加的 `favoriteColor` 未登记、`mustMention` 不是给模型填的），剩下 6 格经**逐格确认**才写入。

```bash
npm run card-doc            # 从 spec 重新生成 docs/CARD.md
npm run card-doc -- --check # 检查文档是否与 spec 一致
```

## 口径与边界

**数据来源**：产品读的是**你本机的游戏文件** —— `%USERPROFILE%\AppData\LocalLow` 下的存档与日志、
`%APPDATA%\Godot\app_userdata`。仓库里**不含任何游戏数据**，也**从不修改你的存档**
（所有测试与演示都在临时目录里的副本上跑）。

**需要区分两件事**：数字有出处，但**适用范围里有我的判断**。以下是明确属于后者的部分：

| 项目 | 说明 |
|---|---|
| **真实云端文生图** | 接口留好了、程序化兜底能跑，但**没有实现**（没有 key，我无法验证 —— 所以不写实现） |
| **真实 LLM 与真实网页抓取** | 链路用注入的 `fetch` 离线验过，**真实网络路径未验证** |
| **长跑验证是注入时钟的** | 验的是引擎逻辑在长时间下的行为。`--real` 那一档才用真实挂钟，受时长限制只能验路径通不通 |
| **过场动画** | `relaxedIdleSec = 10s` 意味着"10 秒没碰键鼠"就算松懈，而看剧情时几分钟不碰键鼠很常见 ⇒ **有在过场里插嘴的风险**。这是当前最值得实测的一条 |
| **OS 空闲检测的长时表现** | `powerMonitor.getSystemIdleTime()` 实测可用，但在几小时尺度上的行为未验证 |
| **解码链只覆盖到解不开为止** | 本机 162 个存档候选里 **61 个（37.7%）完全解开**；剩下的是加密 base64、.NET BinaryFormatter、高熵二进制 —— **不影响可用性**，仅凭"文件被写入"就能驱动时机引擎 |
| **程序化立绘不能凭空造姿势** | 它只做几何变换与风格化，**不可能画出原图没有的姿势**。真正的多姿势要云端 provider |

## 开发者备忘

### 架构

```
游戏日志/存档 ─decode→ 对象 ─diff→ 变化 ─presence→ 该不该开口 ─dialogue→ 回复
                                    ↑                        ↑        ↑
                              角色卡(hard/soft) ────────────┘   记忆库 ┘
      └──── gameio/observe.mjs ────┘     └── agent/session.mjs 串成一局 ──┘
                        app/ = Electron 外壳（桌宠窗 / 设置页 / 人物卡页）

角色卡的来源之一：网上介绍 ─fetch→ 文本 ─fill(填表)→ 逐格确认 → 卡
```

`core/` `gameio/` `dialogue/` `agent/` `art/` `lore/` 都是**零运行时依赖**的纯 Node 模块；
`app/` 只做外壳与接线，业务逻辑全在可离线单测的模块里 —— 所以界面改动不影响数值与时机基线。

### 数据规模

10 个 core 模块 · 3 个引擎 adapter · 6 个 gameio 模块 · 3 种画风 · 7 类桌宠动作 ·
19 个测试套件 / **627 条断言** · 3 份专项文档 + 本 README

### 验证（改动后必跑）

```bash
npm test                              # 627 条断言，19 个套件
```

"桌宠长什么样""填表流程能不能用"不靠描述，靠图和断言。

### 踩坑索引（摘）

完整 73 条在 `docs/HANDOFF.md` §5。几条值得单独提的：

- **capability 曾由"本 tick 产出了什么"推出** ⇒ 没有变化的那一 tick 被打回基线、档位掉回保守档。
  而"没有新变化 + 玩家刚放下手柄"恰恰是最该开口的那一刻 —— 结果是桌宠**几乎永远开不了口**。
  根因是**一个变量回答了两个问题**。现在 capability 是累积的观察事实
- **`silenceDuringPlay` 这个字段名与含义正好相反**（值是"专注期说了话"的违规数）。已改名 `spokeWhileFocused`
- **`moderate` 的待发言 TTL 比 `conservative` 还短** ——「越主动越没耐心」的倒挂。
  TTL 是新鲜度守卫不是节流手段，两档统一为 10 分钟
- **我一度用 PowerShell 的文本管道改源码**，把 `gameio/observe.mjs` 整个搞成了乱码
  （当时仓库还没 `git init`，没有回滚），靠反转 mojibake 再照着重写救回来的 —— 所以 `git init` 该早做

### 模型接入（可选）

不配也能用全部功能 —— 表达层会退回模板档，素材会退回程序化 provider。
在设置页填 provider / baseUrl / model / apiKey 即可（只落本机状态目录，界面上只显示脱敏形式）。
**模型输出永远不直接生效**：它只提议，进不进得去由校验器与你的逐格确认决定。
